## 二、数据层

### 2.1 IndexedDB 5 张表

```
messages       聊天条目                       v1 已有
emotions       情绪记录                       v1 已有
reviews        复盘抽取                       v1 已有
settings       单行用户配置                   v1 已有 + v2.0 加 customName
interviews     用户主动添加的面试日程         v2.1 新增
```

### 2.2 Dexie schema 升级（关键设计）

```ts
class QiChiDB extends Dexie {
  constructor() {
    super('qichi');
    // v1 schema 保留以保证老用户能自动升级
    this.version(1).stores({
      messages: '++id, role, createdAt',
      emotions: '++id, messageId, createdAt, *tags',
      reviews: '++id, messageId, company, jobPosition, hidden, createdAt',
      settings: '++id',
    });
    // v2 schema：只声明新表；老表不动 → Dexie 自动迁移
    this.version(2).stores({
      interviews: '++id, scheduledAt, completedAt',
    });
  }
}
```

**关键点**：
- v(2) 只声明新表，**不重复声明 v1 表**。Dexie 的版本系统会自动 carry forward。
- `Settings.customName` 是新字段但**不参与索引**，所以不需要 schema 升级，老 row 读出来 `customName: undefined` 自然回落到品牌名。
- 老用户升级路径：v1.x APK 直接覆盖安装 v2 APK 即可，IndexedDB 数据保留。Dexie 在首次打开 v2 时跑一次 transaction，加 `interviews` 空表。

### 2.3 Review vs Interview 的语义分工

| 维度 | Review | Interview |
|------|--------|-----------|
| 来源 | AI 从聊天里自动抽取 | 用户主动添加 |
| 时间 | 已发生 | 计划 / 未来 |
| 主键 | 隐式与 message 关联（`messageId`） | 独立 `scheduledAt` |
| 编辑 | v2.2 起可全字段编辑 | v2.1 起可全字段编辑 |

**第一版不做强 link**：日历视图里两者**同日同卡**，用户自己识别。强连接（一场面试同时关联预约 + 复盘）留给 v3。

### 2.4 默认显示名（双名字模式）

```ts
// src/lib/pets.ts
export function getDisplayName(s: { name: PetName; customName?: string }): string {
  return s.customName?.trim() || s.name;
}
```

- `Settings.name`：品牌名（栖栖 / 迟迟），**不可改**，用于"叫回原名"兜底
- `Settings.customName`：用户自定义，**trim 后为空视为未改**
- 所有 UI / LLM 调用都走 `getDisplayName()`，**禁止直接读 `settings.name`**

副作用：
- `PetName` 字面量类型只在品牌名场景使用；LLM prompt 构造函数 `petName` 参数已放宽为 `string`
- `prompts.ts` 的 prompt cache 从 `Partial<Record<PetName, string>>` 改为 `Map<string, string>`（自定义名无穷集合）

## 三、主题系统（v2 暗黑模式）

### 3.1 设计原则

| 元素 | 是否随主题切换 | 理由 |
|------|---------------|------|
| brand 暖橙系（brand / brand-deep / brand-soft / brand-pale） | ❌ 不切 | 是 IP 身份，浅深都温暖 |
| 中性色四档（page / card / subtle / line / ink.*） | ✅ CSS 变量驱动 | 主导深浅观感 |
| mood 辅色（mood-warm / pink / blue / green / purple） | ❌ 暂不切 | 数量少 + 当作 chip 底，浅色在深底上反差强 |
| 语义色（success / notice / danger） | ❌ 不切 | 数量少 + 高语义 |
| 背景插画 | ✅ 按 theme 切图 + 覆盖层兜底 | GA 接入了聊天 / 设置的深色专版（`BACKGROUNDS.chatDark/settingsDark`）；欢迎页等无专版时仍走半透明 `bg-page opacity-55` 兜底 |
| 宠物气泡渐变 | ❌ 不切 | rgba(252,217,168,...)，在深底上是浅暖块，强调"宠物在说话" |

### 3.2 token 实现

**`tailwind.config.ts`**：中性色改为 `rgb(var(--c-x) / <alpha-value>)`，让 Tailwind 的 opacity modifier 仍能用。

```ts
const v = (name: string) => `rgb(var(${name}) / <alpha-value>)`;

colors: {
  brand: { /* 固定色 */ },
  page: v('--c-page'),
  ink: { DEFAULT: v('--c-ink'), soft: v('--c-ink-soft'), ... },
  // ...
}
```

**`globals.css`**：定义 `:root` 与 `:root.dark` 两套 token（8 个变量）。

```css
:root {
  --c-page: 255 248 238;
  --c-ink: 90 62 43;
  /* ... */
}
:root.dark {
  --c-page: 31 26 21;
  --c-ink: 240 226 201;
  /* ... */
}
```

### 3.3 切换实现

**v2.1 从三态简化为二态 toggle**：

```ts
// src/lib/theme.ts
export type Theme = 'light' | 'dark';
```

理由：
- 用户要求"默认浅色 + 点击切换"，auto 不再可见
- 老用户已存 `'auto'` / 非法值 → 自动回退 `'light'`

**防 FOUC**：layout.tsx `<head>` 内联脚本在 React hydrate 前先把 `.dark` 落到 `<html>`。

```ts
// THEME_INIT_SCRIPT
(function(){
  try {
    var t = localStorage.getItem('qichi:theme');
    if (t === 'dark') document.documentElement.classList.add('dark');
  } catch (e) {}
})();
```

**跨 tab 同步**：`useTheme` 监听 `storage` 事件，A tab 改 B tab 自动响应。

### 3.4 主题 UI 入口

`<ThemeToggle />` 组件放在每个主页面的 AppBar `right` slot：浅色显示 `light.svg`、深色显示 `dark.svg`，点击 toggle。

**取代 v2.0 设置页"外观"分组**（一开始是放在设置里的三选一，v2.1 决策改成顶部图标）。

## 四、UI 模式（v2 沉淀）

### 4.1 BottomSheet 装表单（取代居中 Dialog）

字段多的表单一律走 BottomSheet，不用 Dialog：
- 移动端原生体感更好
- 高度灵活（max-h 70~80dvh）
- 顶部一行"保存" + 内容 scroll 区

应用：
- [`InterviewForm`](../../src/components/notebook/InterviewForm.tsx)（新增 / 编辑面试日程）
- [`ReviewEditForm`](../../src/components/notebook/ReviewEditForm.tsx)（编辑复盘）
- [`EmotionDayDetail`](../../src/components/curve/EmotionDayDetail.tsx)（情绪卡片详情）

短表单 / 确认场景仍用 Dialog（[`Dialog`](../../src/components/ui/Dialog.tsx)）：
- 改名 / 删除确认 / 清除数据
- 字段 ≤ 2 个 / 主要是 yes/no

### 4.2 数组字段用 textarea + 一行一条

`questions / mistakes / strengths` 这类字符串数组，编辑时用 textarea：

```ts
// 进入：arr.join('\n')
// 出去：split('\n').map(trim).filter(Boolean)
```

- 优点：实现简洁，移动端键盘体验好
- 取舍：放弃了拖动排序 / 逐条增删的能力，留 v3

### 4.3 同一表单兼新增 / 编辑

InterviewForm 接受 `initial?: Interview` 参数：
- 传 → 编辑模式，预填字段，提交时调 `updateInterview`
- 不传 → 新增模式，提交时调 `addInterview`

useEffect 在 `open` 跳变时同步状态，避免组件常驻不重置。

### 4.4 卡片极简 + 点击展开抽屉（v2.3 关键模式）

情绪卡片 v2.2 把"事件 chips"塞在卡片上，事件多了塞不下（用户反馈）。**v2.3 改成卡片只承载"指示" + 点击进抽屉看完整详情**。

实现：
- 卡片整张是 `<button>`，左 4px mood-tone 边框作为情绪基调暗示
- 抽屉 (`EmotionDayDetail`) 按需 useLiveQuery 查当日 emotions / messages，**冷启动开销不增加**

这是个可复用的模式：以后任何"按日聚合 + 详情多到塞不下"的场景，都该走这个。

## 六、性能 / 兼容关键点

### 6.1 N+1 防御

情绪卡片聚合涉及 `emotions → messages（摘要）→ reviews（事件）`。在 `useEmotionDigest` 里**一次性批量查**：

```ts
const ids = Array.from(wantedMessageIds);
const [msgs, reviews] = await Promise.all([
  db.messages.where('id').anyOf(ids).toArray(),
  db.reviews.where('messageId').anyOf(ids).toArray(),
]);
```

避免每天一次单独查询变成 30+ 次 IndexedDB 调用。

### 6.2 按需查询

`EmotionDayDetail` 不在 list hook 里塞当日全部消息——在 list 上只算聚合 digest，详情**等抽屉打开才挂载** useLiveQuery 拉。冷启动开销不增加。

### 6.3 Dexie 老用户升级

v1 → v2 升级路径：
1. 老用户首次打开 v2，Dexie 检测到 `version: 1`，跑一次 upgrade transaction
2. 加 `interviews` 表（空）
3. 老表 messages / emotions / reviews / settings 数据原样保留
4. `Settings.customName` 字段不存在 → 读出来 `undefined` → `getDisplayName()` 回落到品牌名

**实测建议**：GA 前在装着 v1 数据的设备上覆盖装一次 v2 APK 验证。

### 6.4 主题切换无闪烁

防 FOUC 关键：
- `layout.tsx` 顶部内联脚本在 React hydrate 前同步执行
- `<html suppressHydrationWarning>` 避免 className 不一致的 hydration 警告
- token 用 CSS 变量驱动，切 class 立即生效，无组件重渲染

### 6.5 静态导出兼容

所有新增功能都是客户端组件：
- ThemeToggle / useTheme：`'use client'`
- EmotionDayDetail：`'use client'`
- InterviewForm / ReviewEditForm：`'use client'`

`npm run build:apk`（cross-env BUILD_TARGET=static）不破坏。

## 七、被明确否决的设计

| 否决项 | 原因 |
|--------|------|
| 把所有 mood 色也变成 CSS 变量 | 数量少 + 用作 chip 浅色底，深色上反差强；改造收益 < 复杂度 |
| 给宠物气泡渐变做深色版 | 浅色块在深底上正是"宠物在说话"的强调，反而好看 |
| InterviewForm 用拖拽时间组件（如 react-day-picker） | 引入依赖；原生 `<input type="date">` + `<input type="time">` 在 iOS / Android 都跑得动 |
| 数组字段做"+/-" 卡片式增删 | 实现量大；textarea 在移动端键盘体验已够好 |
| 情绪卡片做横向 swiper | 引入 swiper / framer drag 依赖；纵向列表更朴素 |
| 主题切换做三态（auto / light / dark） | v2.0 试过，v2.1 用户反馈要直接 toggle，auto 不可见 |
| 月度 banner 做强提醒 / 推送 | 违反"不打扰"原则 |
| 情绪卡片每日强制打卡 | 违反 v1 "不要养成机制"原则 |
| 跨设备同步 / 云端备份 | 违反"0 后端 + 隐私优先" |
