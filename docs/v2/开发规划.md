## 一、项目全貌速览（写给"刚回到项目的自己"）

### 1.1 v1 已交付了什么

- **产品**：一只小动物（猫/狗二选一）陪你聊面试糟心事，复盘后台自动生成，长期看心情曲线。
- **4 模块**：聊天 / 小本本（隐性复盘） / 心情曲线 / 我（设置）。
- **核心机制**：用户吐槽 → 宠物说"喵～/汪～" → 用户点翻译展开 LLM 共情人话；同时静默抽情绪 + 面试要素入库。
- **分发**：Vercel 网页 + Android APK（Capacitor 静态导出），同一份代码。
- **隐私架构**：客户端直调 OpenAI 兼容 API，用户自带 key，全部数据存本机 IndexedDB（4 张表：messages / emotions / reviews / settings）。

### 1.2 技术栈现状

| 层 | 选型 | 备注 |
|----|------|------|
| 框架 | Next.js 15 (App Router) + React 19 + TS | 静态导出可用 |
| 样式 | Tailwind 3.4 + 自定义 token（暖橙 + OPPO Sans） | 未引 shadcn |
| 动画 | Framer Motion 12 | 当前宠物姿态是 4 张静态 PNG 切换 |
| 图表 | Recharts 2 | 心情曲线 |
| 存储 | Dexie 4 (IndexedDB) | 无后端 |
| LLM | openai SDK `dangerouslyAllowBrowser` | 客户端直调，CORS 需代理 |
| 打包 | Capacitor 8 → APK | `BUILD_TARGET=static` 切换 |

### 1.3 v2 起点已经有的东西

- ✅ `package.json` 版本已置为 `2.0.0-alpha.1`
- ✅ `docs/v2/PRD.md` 模板已建好（待填）
- ✅ `public/design-refs/欢迎页.html`、`聊天页.html` 两份**高精度视觉参考**（已包含背景插画、6 帧精灵图、新气泡样式）

- ✅ `seed1` 页面（8 个月真实面试旅程的演示数据生成器）

## 二、v2 可以从哪些方向入手（候选分析）

> 每个方向都给一个"为什么值得做 / 工作量 / 主要风险"的速判，便于做收敛。

### 方向 A：视觉升级 —— 把现有功能搬进绘本化新视觉

**来源**：`public/design-refs/` 下两份 HTML 已经把新视觉钉死了。
**核心改动**：
- 全屏背景插画（欢迎页猫狗双陪伴 + 月亮云朵；聊天页爪印路径）
- 宠物从 4 张 PNG 升级为 **6 帧精灵图呼吸动画**（聊天页 HTML 里用了 `background-position` + steps(1)）
- 气泡视觉重做（玻璃磨砂感、宠物气泡渐变橙）
- 翻译按钮从行尾改到**气泡旁圆形按钮**
- 欢迎页加诗经引用 + 艺术字 logo

**为什么值得做**：v1 用户反馈中没明确写"丑"，但视觉是**情绪类产品的关键护城河**。两份高完成度 HTML 已经把不确定性消解了。
**工作量**：中等（约 2-3 周，要做素材整理 + 5 个页面适配 + 字体引入）。
**主要风险**：背景插画素材依赖（猫狗双陪伴图、聊天页爪印图）需要 AI 生图或手绘——**这是阻塞项**。
**收益**：观感跃迁，作品集质感，朋友试用门槛降低。

### 方向 B：功能补强 —— 把 v1 PRD §11 列的局限挑几个修

来自 v1 PRD 已知局限的清单（按解决难度排序）：

| # | 局限 | 解决方案 | 工作量 | 价值 |
|---|------|---------|-------|------|
| 1 | 宠物名不可改 | 设置页加输入框，DB 已有字段 | 0.5 天 | 低（验证 H2 假设的尾巴） |
| 2 | 暗黑模式缺失 | Tailwind dark 变体 + token 双色 | 2-3 天 | 中（深夜场景刚需） |
| 3 | 没有面试日历 | 把 reviews 按日聚合，月历视图 | 2-3 天 | 中（"我这周面了几场"的直观回答） |
| 4 | "无面试日"无引导 | 聊天空状态加碎碎念引导 prompt | 1 天 | 低-中 |
| 5 | 月度总结被动触发 | 月初聊天页顶 banner 提示 | 1 天 | 中（拉回头率） |
| 6 | 宠物动画静态 | 见方向 A 的精灵图改造 | 与 A 重合 | - |
| 7 | CORS 强依赖 chatanywhere | 见方向 D | - | - |
| 8 | 数据无跨设备同步 | 端到端加密云同步 | 1-2 周 | 高但复杂 |

**为什么值得做**：每项都是独立小特性，可以"挑选式"做，组合灵活。
**工作量**：单项 0.5-3 天，挑 3-4 项即可作为 v2 的功能侧。
**主要风险**：单做 B 容易让 v2 像"v1 patch"，缺少"质变感"。

### 方向 C：体验深化 —— 流式翻译 / 宠物互动 / 跨设备同步

- **流式翻译**：当前 `translateMessage` 是一次性返回（[src/lib/llm-client.ts:114](src/lib/llm-client.ts)），改成 SSE 流式可以让翻译"逐字浮现"，跟猫/狗慢吞吞的语气更契合。
- **宠物互动手势**：摸摸/喂食/拍头，触发不同姿态切换。
- **跨设备同步**：v1 局限 4，需要后端（或挂 Supabase / Firebase），与"无后端"原则冲突。

**为什么值得做**：差异化更强。
**工作量**：流式 1-2 天；手势 3-5 天；跨设备 1-2 周（且会引入服务器成本）。
**主要风险**：跨设备会破坏 v1 "0 后端、隐私优先"的架构原则；手势需要更多动画素材。

### 方向 D：部署门槛降低 —— 解决 CORS 痛点

v1 PRD §11 局限 1：朋友配 chatanywhere 教育成本高。可选方案：
- **D1**：Vercel Edge Function 做中转代理（用户填官方 OpenAI key，走我们的边缘节点）——成本可控但失去"0 后端"。
- **D2**：内置 [`@xenova/transformers`](https://huggingface.co/docs/transformers.js) 跑本地小模型（QWen-0.5B 量级），翻译 / 情绪标签不走云。——APK 体积会膨胀、首次加载慢。
- **D3**：在设置页内置"一键填好 chatanywhere 配置"快捷按钮 + 详细教程图。——最便宜。

**为什么值得做**：直接影响试用人数（v1 §10.1 待收集指标）。
**工作量**：D3 半天；D1 中等；D2 大。
**主要风险**：D1/D2 都改变了架构边界。

## 三、推荐主线：A + 局部 B（暗黑 + 面试日历 + 改名）+ D3

### 3.1 为什么这么选

1. **A 的不确定性最低**：HTML 已钉死，看得见摸得着，可视化反馈快，做完直接有质变感。
2. **B 里挑"暗黑模式 + 面试日历 + 宠物改名"**：每一项都和 A 的视觉重做有协同（token 拓展、新页面顺手做）。
3. **D3 顺手做**：成本只有半天，但能直接消化掉 v1 §11 局限 1。
4. **明确不做** C 的跨设备和"流式翻译"，避免架构动摇。

### 3.2 取舍依据

| 评估维度 | 主线（A+B 局部+D3） | 纯 B | 含 C 的扩展 |
|---------|-----|-----|-----|
| 视觉跃迁 | ✅ 强 | ❌ 弱 | ✅ 强 |
| 架构稳定 | ✅ 不动 | ✅ 不动 | ⚠️ 动 |
| 工作量 | 中（~4 周） | 小（~2 周） | 大（~6 周以上） |
| 风险 | 仅素材风险 | 容易像 patch | 架构 + 后端成本 |

> 如果只想"小步迭代不大改"，可以退回纯 B。如果想做大版本，再叠 C。

## 五、明确**不做**（v2 边界 · 防 scope creep）

- ❌ 跨设备同步 / 云端备份（破坏"0 后端"原则）
- ❌ 流式翻译（增益不够大，单独立项）
- ❌ 宠物互动手势（喂食/拍头，素材成本高）
- ❌ 更多宠物种类（v1 PRD 已排除，继续延续）
- ❌ 树洞 / 社交 / 评论
- ❌ 自建 LLM 中转后端（保留 BYOK 架构）
- ❌ 多 IP 切换 / 换装

## 六、关键决策点（需要拍板，不要"边做边定"）

> 这些一旦做错就要返工，建议先想清楚再开阶段 1。

| # | 决策 | 选项 | 建议 |
|---|------|------|------|
| **D1** | 背景插画素材来源 | AI 生图 / 找免费素材 / 自画 | AI 生图 + 后期 PS 调色（最快） |
| **D2** | 精灵图来源 | 现有 4 张 PNG 拼 / 重画 6 帧 / AI 生成多帧 | 先拼现有 PNG 做 baseline；正式版重画 |
| **D3** | 字体引入方式 | next/font/local / CDN / Google Fonts | next/font/local（APK 离线可用） |
| **D4** | 暗黑模式深色背景插画 | 重画一套 / 同图加深色覆盖层 | 覆盖层（成本低） |
| **D5** | 视觉重做时是否同步重构组件 | 同步重构 / 仅改样式 | 仅改样式（降低风险） |
| **D6** | v2 视觉 baseline 完成前是否对外发 alpha | 不发 / 发给 1-2 个朋友 | 发，收"质感"侧反馈 |

## 七、风险与对策

| 风险 | 概率 | 影响 | 对策 |
|------|------|------|------|
| 背景插画 AI 生图反复调不出"猫狗双陪伴"那个味 | 高 | 阻塞阶段 2 | 先用占位灰图跑通代码层，素材并行迭代 |
| 6 帧精灵图比 4 张 PNG 体积大很多，APK 膨胀 | 中 | 影响下载体验 | 用 WebP + 控制单图 ≤ 200KB |
| 暗黑模式下背景插画穿帮 | 中 | 视觉不一致 | 加 `mix-blend-mode` 或半透明深色覆盖 |
| 改名后历史消息里的"栖栖说" / "迟迟说"对不上 | 低 | 数据一致性 | 显示用当前名字渲染历史，不改 DB |
| OPPO Sans 字体版权 | 低 | 法律 | 用 OPPO 官方公开免费版本，注明出处 |
| 视觉做完发现 v1 用户其实更喜欢旧版 | 低-中 | 返工 | 阶段 2 末发 alpha 给朋友试用，收反馈 |
