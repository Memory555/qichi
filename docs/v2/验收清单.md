## F. 发布动作（验收全过后）

```bash
# 1. typecheck 兜底
npm run typecheck

# 2. 合并 v2-dev → main
git checkout main
git merge v2-dev --no-ff -m "Release v2.0.0"
git push origin main

# 3. tag + push tag
git tag -a v2.0.0 -m "v2.0.0：暗黑模式 / 面试日程 / 情绪卡片 / 宠物改名 / 编辑复盘"
git push origin v2.0.0

# 4. v2-dev 也推一下保持同步
git push origin v2-dev

# 5. 打 APK
npm run build:apk
npx cap sync
npx cap open android
# Android Studio: Build → Build Bundle(s) / APK(s) → Build APK(s)
# 出包路径：android/app/build/outputs/apk/debug/app-debug.apk
# 可以重签为 release 版本（v1 部署指南有详细流程）

# 6. Github Release
# 上传 .apk + 写 Release Notes（直接 copy v2-Release-Notes.md 主体）
```

## G. 退路

如果发布后发现严重问题：

- **代码回滚**：`git revert -m 1 <merge_commit>` 把 merge 撤掉，main 回到 v1 状态
- **数据兼容**：v2 的 dexie schema 改动是**单向**的——一旦升上 v(2) 用户的 IndexedDB 就有 interviews 表了。回退 v1 不会报错（v1 schema 不知道这张表，但 Dexie 不删未声明的表）
- **APK 回退**：用户手动卸载 v2 装 v1，**数据保留**（IndexedDB 与 APK 包名绑定，包名不变就在）
