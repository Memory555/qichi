## 阶段 4 · 暗黑模式

### 4.1 设计原则
- **brand 暖橙系不动**：是 IP 身份，浅深都温暖
- **中性色（page/card/subtle/line/ink 四档）** 走 CSS 变量驱动，深色覆写
- **背景插画** 通过半透明 page 覆盖层"沉色"，不重画素材

### 4.2 变更

**[tailwind.config.ts](../../tailwind.config.ts)**
- 加 `darkMode: 'class'`
- `page / card / subtle / line / ink.*` 改成 `rgb(var(--c-x) / <alpha-value>)`
- `brand / mood / success / notice / danger / chip` 保留色值不变

**[src/app/globals.css](../../src/app/globals.css)**
- 新增 `:root` 与 `:root.dark` 两套 token（8 个变量：page/card/subtle/line + ink 四档）
- `html, body` 的 background/color 改为 `rgb(var(--c-...))`
- 删除原 `theme('colors.page')` 的 background 写法（与 token 重复）

**新增 [src/lib/theme.ts](../../src/lib/theme.ts)**
- `Theme = 'auto' | 'light' | 'dark'`
- `readTheme / writeTheme / resolveTheme / applyTheme`
- `THEME_INIT_SCRIPT`：内联脚本，layout 顶部跑，**防 FOUC**

**新增 [src/hooks/useTheme.ts](../../src/hooks/useTheme.ts)**
- 从 localStorage 读 → applyTheme → React state 同步
- `auto` 模式监听 `prefers-color-scheme` 变化

**[src/app/layout.tsx](../../src/app/layout.tsx)**
- `<html suppressHydrationWarning>` + `<head><script>THEME_INIT_SCRIPT</script></head>`

**[src/components/layout/BgImage.tsx](../../src/components/layout/BgImage.tsx)**
- 加一层 `hidden bg-page opacity-[0.55] dark:block` 实现暗色覆盖

**[src/app/(main)/settings/page.tsx](../../src/app/(main)/settings/page.tsx)**
- 新增 `ThemeRow` 三选一组件（带 radio 视觉）
- 新增 Section title="外观"，dataloader 三行

### 4.3 已知边界
- mood / chip 辅色未做深色变体（数量少，后续按需修复）
- 用户气泡 `bg-card/90` 在深色下变成深棕半透明，效果可接受
- 宠物气泡渐变保留 `rgba(252,217,168,...)` 不变 → 深色下是浅暖块，视觉对比强，**符合"宠物在说话"的强调**

## 阶段 B · 情绪卡片

### 设计
- **数据来源**：从已抽取的 emotions 按日聚合，**不强制用户每日打卡**（保留 v1 "不要养成机制" 原则）

  - import 改 `ScheduleCalendar`

- **hidden 的 review 不计入**（用户点过"这条不算"的视作放下）
- **无字段的 review 跳过**：避免出现空 chip
- **range → limit 映射**：7→7、30→30、0→60（全部时 60 张封顶，分页留 v3）

# v2.3 情绪卡片重设计

> 用户反馈："情绪卡片设置得不太好" + "事件多了没办法罗列完，可以考虑点击查阅"。
> 实施日期：2026-06-12（接 v2.2 当日推进）

## 设计变更

### v2.2 的卡片问题

```
v2.2 卡片                    ← 一张卡装太多东西
┌────────────────────────────────────┐
│ [大色块]   [事件 chip][事件 chip]   │ ← 事件多了塞不下
│ 2026.6.12  [挫败][焦虑] · 7 条      │
│ 高 8.2    今天三面被反问问懵了…     │
└────────────────────────────────────┘
```

问题：
- 左侧 56px 大色块 + 右侧 chip 群 + 摘要，**信息密度过高**
- 事件 chip 限 3 个 + `+N`，**多了仍然乱**
- "高/平/低" 三档分级**信息颗粒太粗**

### v2.3 的卡片

```
v2.3 卡片                    ← 极简、信息分层
┃ 2026.6.12  [挫败]      2 场 · 7 条
┃ ▓▓▓▓░░░░░░ 3.2          ›
↑ 左 4px mood-tone 边框
```

点击卡片 → BottomSheet 展开 **EmotionDayDetail**：
- 情绪轨迹（每条 emotion 一根小条，高度=score，颜色=主标签 mood-tone）
- 这天面的（**全部 events，不再限制 3 个**）
- 那天你说的（前 5 条 user message，超过提示"可以去小本本里翻"）

## 关键设计取舍

| 选项 | 选择 | 理由 |
|------|------|------|
| 左侧色块 vs 4px 边框 | 4px **边框** | 表达 mood 但不占空间；卡片高度从 ~88px 降到 ~58px |
| mini 折线 vs mood 横条 | **横条** | 单条卡片小时颗粒数据不足；横条朴素够用 |
| mood 横条配色 | 统一暖橙 brand | 配色已被 chip + 边框承担，bar 再分色就乱 |
| 事件 chip 在卡片上 | **去掉** | 多了塞不下（v2.2 经验）；统一进抽屉 |
| 卡片点击区域 | **整张卡片** | 一目了然，右侧 `›` 暗示可进 |
| 抽屉的"查看全部"跳转 | **不跳，只展示前 5 条** + 文字引导去小本本 | 避免 BottomSheet 嵌套导航；保留用户路径选择权 |
| 详情数据加载策略 | **抽屉打开时按需查** | 不在 list hook 里塞当日全部消息；冷启动只算聚合，详情按需 |

## 变更

### 新增

- **[src/components/curve/EmotionDayDetail.tsx](../../src/components/curve/EmotionDayDetail.tsx)**
  - 三段：情绪轨迹（≥2 条才显示，1 条没必要） / 这天面的 / 那天你说的
  - 用 `db.emotions.where('createdAt').between(...)` + `db.messages.where('createdAt').between(...)` 按日切片查询
  - 三段都空时显示"这天数据不太够，再来跟我说说？"治愈兜底

### 重写

  - 抽 `EmotionCardItem` 内部组件

  - 卡片整张是 button，点击触发 `setOpenDate(d.date)`
  - 主体外加 `<BottomSheet>` 包装 `<EmotionDayDetail>`
  - 删除卡片上的事件 chips、删除卡片摘要（统一进抽屉）

### 保留

## 体验对比

| 指标 | v2.2 | v2.3 |
