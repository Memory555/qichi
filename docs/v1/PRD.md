## 一、产品定位

### 1.1 一句话价值主张

> **选一只小动物陪你聊面试糟心事——你只管吐槽，复盘它替你默默记着。**

### 1.2 产品形态

一款 **以小动物陪伴为入口** 的轻应用：
- **倾诉**作为第一交互
- **复盘**作为后台静默副产品
- **情绪追踪**作为长期回看的锚点

同一份代码同时以**网页（Vercel）** 和 **Android 原生（Capacitor APK）** 两种形态分发，朋友自带 OpenAI 兼容 API key 使用。

---

## 二、目标用户

### 2.1 核心人群

求职 / 面试期人群，覆盖三类：
- 应届毕业生
- 1-3 年跳槽者
- 焦虑型长期求职者

### 2.2 共性特征

1. 持续有面试场次
2. 面试后情绪波动强
3. **抗拒填表式复盘**
4. 偏好治愈系 / 拟人化交互

### 2.3 典型使用场景

- 面试结束走出大厦的地铁上
- 被拒邮件后的深夜
- 连续 3 场没下文的周末

### 2.4 替代方案对比

| 替代方案 | 没解决的痛点 |
|---------|-------------|
| 微信小号自言自语 | 没有回应，加倍空虚 |
| Notion 面经表 | 表单式，写两次就弃 |
| 跟朋友倾诉 | 怕烦人、无法持续 |
| ChatGPT | 不够"在地"、没有持续记忆 |

## 三、核心痛点 × 差异化

### 3.1 用户痛点（v1 解决的）

| # | 痛点 | v1 应对 |
|---|------|--------|
| 1 | 复盘工具太"工业" | 聊天式倾诉，复盘后台自动 |
| 2 | 倾诉无处去 | 24h 在线的小动物陪伴 |
| 3 | 情绪与复盘割裂 | 倾诉中静默抽取面试要素 |
| 4 | 长期心态盲区 | 月度心情曲线 + 拟人化总结 |

### 3.2 跟常规面试复盘工具的差异化

| 常规工具 | 栖迟 v1 |
|---------|---------|
| 表单填写 / 题库归档 | 聊天倾诉，复盘后台自动生成 |
| 中性 AI 助手语气 | 猫 / 狗小动物人格，先共情后才（可能）复盘 |
| 数据导向（成功率、错题率） | 情绪导向（心理曲线、心态变化） |
| 强目的性，焦虑放大 | 弱目的性，安全感优先 |

## 四、核心用户故事（v1 必须满足）

1. **作为一个刚结束面试的人**，我希望打开网页就能跟我的宠物吐槽，不被任何表单拦截
2. **作为一个第一次使用的人**，我希望能选一只我喜欢的小动物（猫或狗）作为我的陪伴
3. **作为一个不擅长表达的人**，我希望宠物的回复像朋友而不是客服，能让我继续说下去
4. **作为一个面试很多场的人**，我希望系统自动记住我面试了什么，不用我手动整理
5. **作为一个长期焦虑的人**，我希望能看见自己心态的变化曲线，而不是错题列表
6. **作为一个注重隐私的人**，我希望我的倾诉默认只存在我自己的设备上

## 六、宠物差异化设计

> 让两种宠物在"性格"上略有区分，提供用户情绪投射选择。

| 维度 | 🐱 橘猫"栖栖" | 🐶 柴犬"迟迟" |
|------|--------------|--------------|
| 性格定位 | 慵懒、安静、不多说话 | 温和、踏实、稳稳陪着 |
| 适合用户 | 想要冷静空间、不需要太多回应 | 想要被稳稳接住、需要持续陪伴 |
| 默认叫声 | "喵～" | "汪～" |
| 翻译后语气示例 | "嗯…我懂，那一瞬间是会发懵的。" | "我在呢，慢慢说，不急。" |
| 待机动作 | 蜷缩、偶尔甩尾 | 趴着、偶尔抬头 |
| 情绪联动样式 | 表情细微、姿态变化 | 表情温和、靠近动作 |

## 七、关键交互流程（v1 闭环）

```
首次进入
    ↓
选择陪伴宠物（猫 / 狗）→ 进入「我 → AI 配置」填 API key
    ↓
进入聊天主界面（宠物已等在那里）
    ↓
用户在聊天框吐槽今天的面试 / 心情
    ↓
宠物回复"喵～/汪～" + 表情/动作联动
    ↓
用户点击"翻译" → 展开 LLM 共情人话
    ↓
（后台静默）：情绪打标签 + 抽取面试要素 → 写入 IndexedDB
    ↓
对话自然结束 / 切换标签页
    ↓
用户可选择性进入「心情曲线」回看波动，或「小本本」查看复盘
    ↓
（月底自动）：拟人化月度总结生成
```

## 八、技术架构（v1 已落地）

### 8.1 技术栈

| 层 | 选型 | 备注 |
|----|------|------|
| 前端框架 | **Next.js 15 (App Router) + React 19 + TypeScript** | 比原计划 Next 14 升了一版 |
| 样式 | Tailwind CSS 3.4 + 自定义 design token（暖橙 + OPPO Sans） | 未引入 shadcn/ui，直接 Tailwind |
| 动画 | Framer Motion 12 | 未引入 Lottie，PNG + Framer 淡入足够 |
| 图表 | Recharts 2 | 情绪折线图 |
| 存储 | Dexie 4（IndexedDB） | 本地优先，无后端 |
| LLM | openai SDK，`dangerouslyAllowBrowser: true` | **客户端调用**（v1 后期重构） |
| 打包 | Capacitor 8 → Android APK | 通过 `BUILD_TARGET=static` 切换 |
| 部署 | Vercel + GitHub Release（APK） | 双路径 |

### 8.2 v1 架构演进

| 阶段 | LLM 调用 | API Key 来源 |
|------|---------|-------------|
| v1.0.0 早期 | 服务端 `/api/translate` 等 | Vercel 环境变量（开发者） |
| **v1.0.0 最终** | **客户端 `lib/llm-client.ts`** | **用户在设置页填，存 IndexedDB** |

**为什么改成客户端**：
1. 静态导出兼容（支持 Capacitor APK）
2. 0 后端成本
3. 用户自带 key 规避 Token 风控

### 8.3 ⚠️ CORS 必填代理

OpenAI 官方 API 不发 CORS 头，浏览器直连必拒。v1 要求用户配 chatanywhere 等 CORS 代理：

```
Base URL: https://api.chatanywhere.tech/v1
```

详见 `docs/v1/部署与分发指南.md` 的 A4 章节。

## 九、数据模型（v1）

IndexedDB 共 4 张主表（Dexie）：

| 表 | 字段（关键） | 用途 |
|----|------------|------|
| `settings` | `pet`, `name`, `openaiKey`, `openaiBaseUrl`, `openaiModelMain`, `openaiModelFast` | 用户配置 + AI 配置 |
| `messages` | `text`, `role`, `translatedText`, `emotionScore`, `createdAt` | 聊天记录 |
| `notes` | `position`, `question`, `failure`, `messageId`, `createdAt` | 复盘小本本（隐性抽取） |
| `summaries` | `monthKey`, `content`, `createdAt` | 月度总结缓存 |

**所有数据本地 IndexedDB，不上传任何服务器**。

## 十一、已知局限（留给 v2 看）

> 这些是 v1 上线后**自己用 / 试用反馈中识别出的问题**，作为 v2 立项的输入。
> ⚠️ 但**不构成 v2 必须解决**的约束 —— v2 可以选择性应对。

1. **CORS 强依赖 chatanywhere** —— 用户教育成本高，部分朋友不会配
2. **宠物动画相对静态** —— 4 种姿态切换，缺少深度互动
3. **月度总结被动触发** —— 用户不一定每月主动打开
4. **数据无跨设备同步** —— 换设备数据丢失
5. **没有面试日历视图** —— 无法直观看到"我这周面了几场"
6. **没有"无面试日"的引导** —— 没面试时容易没东西可聊
7. **宠物名不可改** —— v1 阶段为简化体验固定名字，但 H2 假设（命名提升粘性）未真正验证
8. **暗黑模式缺失** —— 深夜倾诉场景下暖橙偏刺眼

## 十二、风险记录（v1 已应对）

| 风险 | v1 应对方式 |
|------|------------|
| LLM 共情回复"太 AI 味" | 猫 / 狗各写一版 prompt + few-shot 示例 |
| 隐性抽取漏抽 / 误抽 | "小本本"提供手动编辑入口兜底 |
| 用户没那么多面试可聊 | 允许"无面试日"碎碎念，不强推养成打卡 |
| 隐私担忧 | 本地存储 + 设置页明确告知"数据不出端" |
| API key 泄露 | BYOK 模式 + 仅本地 IndexedDB |
| iOS 用户无 APK | Vercel 网页 + Safari「添加到主屏幕」 |
