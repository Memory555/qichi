# 从 Idea 到落地：最小单元版

> 适用于个人项目 / 独立开发者 / 早期创业小团队。原则：**角色不缺位，但人头可叠加**。

---

## 一、最小阶段（6 步）

| 阶段 | 输入 | 输出 | 核心动作 |
|------|------|------|----------|
| **1. 想法验证** | 灵感、用户痛点、竞品观察 | 一句话价值主张 + 目标用户假设 + 是否值得做的判断 | 用户访谈 5~10 人、竞品扫描、桌面研究 |
| **2. MVP 定义** | 验证后的核心问题 | 一页 PRD（功能清单 + 优先级 + 成功指标） | 砍需求、定 MVP 范围、定北极星指标 |
| **3. 设计** | PRD、用户旅程 | 可点击原型（Figma 即可） | 流程图 → 线框 → 高保真 |
| **4. 开发** | PRD + 原型 | 可上线的产品（含基础埋点） | 技术选型、编码、自测、部署 |
| **5. 发布与冷启动** | 可用产品 | 真实用户 + 初始数据 | 灰度上线、种子用户引入、监控告警 |
| **6. 数据迭代** | 用户反馈、行为数据 | 下一版 backlog | 数据复盘、AB 测试、版本规划 |

> 与完整流程相比，砍掉了：独立用研、独立架构评审、独立 QA、独立运维、独立法务。**它们没有消失，而是融入其他角色**。

---

## 二、最小团队画像（4 个角色 / 可压缩到 1~2 人）

### 角色 1：产品负责人（Founder / PM 合一）
- **定位**：决定"做什么"和"不做什么"，对方向负责
- **能力**：用户访谈、需求拆解、写一页 PRD、基础数据分析（SQL/Excel）
- **思维方式**：第一性原理、价值取舍（80/20）、用户视角

### 角色 2：设计师（UX + UI 合一）
- **定位**：决定"用户怎么用"和"看起来怎么样"
- **能力**：信息架构、Figma 原型、设计系统、可用性常识
- **思维方式**：用户旅程视角、奥卡姆剃刀（能不加就不加）、品牌一致性
- **可省略场景**：B 端工具类项目可由开发直接用现成组件库（shadcn/Ant Design）出图

### 角色 3：全栈工程师（前端 + 后端 + DevOps 合一）
- **定位**：把设计稿变成可访问的产品，并保证它别挂
- **能力**：一门主语言 + 一个全栈框架（Next.js / Nuxt / Django）、数据库基础、云部署（Vercel / 云服务器）、基础监控
- **思维方式**：MVP 心态（先跑通再优化）、安全底线、可观测优先
- **隐含承担**：架构设计、测试、运维、合规自查

### 角色 4：增长负责人（运营 + 市场合一）
- **定位**：把产品推到用户面前，并让他们留下来
- **能力**：内容写作、社群运营、渠道投放基础、漏斗分析
- **思维方式**：增长杠杆、ROI 意识、用户共情
- **早期常见做法**：由 Founder 兼任，亲自下场做用户运营

## 四、最小流程下容易踩的坑

1. **跳过验证直接开发** —— 最大的浪费不是写错代码，而是做了没人要的产品
2. **MVP 不够 M** —— "最小"是关键，砍到不能再砍才上线
3. **设计追求完美** —— 早期能用 > 好看，Figma 别画太久
4. **没埋点就上线** —— 上线第一天就要能回答"有多少人用、用了什么"
5. **一个人扛所有角色但没节奏** —— 必须按周切换角色，比如周一产品、周二三四开发、周五运营

---

## 五、一句话总结

> **最小单元 = 6 个阶段 × 4 个角色（可叠加到 1 人）**
> 重点不是"流程多完整"，而是"每个阶段是否被认真对待过 10 分钟"。
