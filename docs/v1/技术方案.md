## 2. 关键技术决策

### 2.1 为什么前端用 IndexedDB 而不是 SQLite？

- **本地优先 + 不出本地** 是产品承诺，必须浏览器原生方案
- IndexedDB 是浏览器唯一的结构化大容量存储（localStorage 5MB 不够）
- Dexie 是 IndexedDB 的成熟封装，API 比原生 IndexedDB 友好 10 倍
- 替代品 SQLite-wasm 太重（~600KB），收益不值

### 2.2 为什么 LLM 调用走 API Route 而不直接前端调？

- **API Key 不能暴露在前端** —— OPENAI_API_KEY 一旦在浏览器可见，任何人都能盗刷
- Next.js API Route 是天然的"后端代理"
- 服务端调 openai SDK，前端只 `fetch('/api/translate')`

### 2.3 为什么用 OpenAI GPT？

- **生态成熟**：openai SDK 是 LLM 工程的事实标准；很多代理（Azure / OpenRouter / 国内中转）都兼容这套格式
- **JSON Mode 可靠**：gpt-4o + `response_format: json_object` 让 P2/P3 抽取结果稳定可解析
- **gpt-4o-mini 极便宜**：单次抽取 < $0.0001，每天 100 条用户消息总成本 < $0.05
- **灵活切换**：通过 `OPENAI_BASE_URL` 可一键切到任何 OpenAI 兼容服务（含国内可用代理）

### 2.4 为什么不用 Lottie 而用静态 PNG + 过渡？

- 8 张精灵图（猫狗各 4 状态）已就绪，体积 ~5MB/张
- Lottie 制作成本高、维护门槛高
- Framer Motion 做姿态切换的淡入淡出 + scale 呼吸 已足够"动态感"
- 未来 Lottie 化是 P2 优化项，不阻塞 MVP

### 2.5 为什么 P2 + P3 并行调用？

- 用户发完一条消息后，**前端立即显示"喵～/汪～"**，不阻塞
- 后台 fire-and-forget 调 P2 情绪标签 + P3 面试要素抽取（并行）
- 失败兜底：P2/P3 都失败也不影响主流程（曲线少一个点 / 小本本少一条）

## 3. 数据模型

### 3.1 IndexedDB 表结构（Dexie）

详见 `src/lib/db.ts`。

```typescript
messages: '++id, role, createdAt'
emotions: '++id, messageId, createdAt, *tags'
reviews:  '++id, messageId, company, jobPosition, hidden, createdAt'
settings: '++id'  // 仅一行，存当前选定的宠物
```

### 3.2 数据流图（单次消息发送）

```
用户在输入框打字
    │
    ├──→ 触发 listen 姿态（前端状态）
    │
点击发送
    │
    ├──→ 写 messages (role=user)
    │
    ├──→ 立即 UI 显示用户气泡 + "喵～/汪～" 气泡
    │
    ├──→ 后台并行（不等结果）:
    │     fetch('/api/extract', { text }) ─→
    │         server: P2 + P3 并行调 Claude Haiku
    │         返回: { emotion, ner }
    │     ←─ 客户端写 emotions / reviews
    │     ←─ 如果 emotion.score ≤ 3，前端切 empathy 姿态
    │
    └──→ 等用户点击「翻译」时:
          fetch('/api/translate', { text, petType, petName }) ─→
              server: P1-CAT or P1-DOG，Claude Sonnet
              返回: { translated }
          ←─ 客户端写 messages[pet].translatedText
          ←─ UI 展开翻译气泡
```

### 3.3 状态机：宠物姿态切换

```
                 默认
                  │
                 idle
                  │
                  │ 用户开始打字
                  ▼
                listen ←──────────┐
                  │                │
                  │ 发送完成        │ 用户继续打字
                  ▼                │
            判断 recentScore       │
            ┌─────┴─────┐          │
          ≤ 3        > 3           │
            │           │           │
         empathy       idle         │
            │           │           │
            └───────────┴───────────┘
                继续聊天 / 切页面
```

代码实现见 `src/types/index.ts` 的 `resolvePetPose()`。

## 4. 路由设计（App Router）

```
src/app/
├── layout.tsx                     ← 根布局：字体加载、Toaster、全局 Provider
├── page.tsx                       ← 路由分发：判断是否首次进入
│
├── onboarding/
│   └── page.tsx                   ← 引导流（欢迎 + 选择宠物）
│
├── (main)/                        ← 路由组：带底部 Tab Bar 的页面
│   ├── layout.tsx                 ← 带 Tab Bar + DecorBackground + Particles
│   ├── chat/page.tsx              ← 聊天主页（默认）
│   ├── notebook/page.tsx          ← 小本本
│   ├── curve/page.tsx             ← 心境曲线
│   └── settings/page.tsx          ← 设置（"我"）
│
├── about/                         ← 独立页（无 TabBar）
│   ├── page.tsx                   ← "这是个什么"
│   └── easter-egg/page.tsx        ← 「衡门之下，可以栖迟」彩蛋
│
├── reset/page.tsx                 ← 调试：清空数据
├── seed/page.tsx                  ← 调试：写入示例数据
│
└── api/
    ├── translate/route.ts         ← P1 共情翻译
    ├── extract/route.ts           ← P2 + P3 并行抽取
    └── monthly/route.ts           ← P5 月度总结
```

**路由判断**（`src/app/page.tsx`）：
- 读 `settings` 表，若无记录 → redirect `/onboarding`
- 有记录 → redirect `/chat`
- `(main)/layout.tsx` 也做兜底：进入任何 main 路由时若 settings 不存在 → 自动跳引导

**装饰层结构**（在 `(main)/layout.tsx` 内）：
- `<DecorBackground />` z-0：theme = chat/me 返回 `<BgImage>`，theme = notebook/curve 返回动画 SVG
- `<Particles />` z-0：全局 22 个暖光点
- `<main className="relative z-10">` 装内容
- `<TabBar />` flex 自然层，bg-page 遮装饰

## 5. API Route 设计

### 5.1 `POST /api/translate`

| 项 | 内容 |
|----|------|
| Body | `{ text: string, petType: 'cat' \| 'dog', petName: string }` |
| Response | `{ translated: string }` |
| 模型 | `gpt-4o`（main） |
| 错误兜底 | 4xx/5xx 时前端显示"我有点走神了，再点一下？" |
| 限流 | 服务端用简单 LRU + 时间窗口，每 IP 每分钟最多 10 次 |

### 5.2 `POST /api/extract`

| 项 | 内容 |
|----|------|
| Body | `{ text: string }` |
| Response | `{ emotion: {...}, ner: {...} \| null }` |
| 模型 | `gpt-4o-mini`（fast，JSON mode） |
| 调用 | 服务端 `Promise.all([extractEmotion(), extractInterviewInfo()])` |
| 错误兜底 | 任一失败返回默认值，不抛错 |

### 5.3 `POST /api/monthly`

| 项 | 内容 |
|----|------|
| Body | `{ petType, petName, monthlyData: {...} }` |
| Response | `{ summary: string }` |
| 模型 | `gpt-4o`（main） |
| 触发 | 用户首次进入"曲线"页且当前月份首次访问时调用 |

## 6. 状态管理策略

| 状态类型 | 方案 |
|----------|------|
| **持久化数据**（消息 / 情绪 / 复盘 / 设置） | Dexie + `dexie-react-hooks` 的 `useLiveQuery`（自动响应 DB 变更） |
| **临时 UI 状态**（输入框值 / 翻译展开 / 当前姿态） | React `useState` |
| **跨页面状态**（当前宠物） | `useCurrentPet` Hook，内部走 `useLiveQuery(db.settings.toArray)` |
| **服务端缓存** | Next.js 自带，无需 SWR / React Query |

> **不引入** Redux / Zustand / Jotai —— 项目体量不需要。

## 7. 性能策略

### 7.1 首屏加载

| 优化 | 目标 |
|------|------|
| OPPO Sans 子集化 | 单字重 ~150-300 KB（vs 原 ~5 MB） |
| 精灵图 lazy load | 仅当前姿态加载 1 张（vs 全 8 张） |
| 字体 `font-display: swap` | 避免空白闪烁 |
| `next/image` 自动 WebP | 体积再降 30% |
| App Router RSC 默认 | 减少首屏 JS |

### 7.2 运行时

- 输入框 debounce 200ms 避免频繁触发 listen 姿态
- 宠物精灵图切换用 Framer Motion 的 AnimatePresence 而非 React 重新挂载
- 历史消息分页加载（每页 50 条，无限滚动）
- IndexedDB 查询用 Dexie 的 `*tags` 索引加速情绪标签筛选

### 7.3 LLM 成本控制

| Prompt | 模型 | 单次成本（参考） |
|--------|------|------------------|
| P1 共情 | gpt-4o（仅用户点翻译） | ~$0.001-0.003 |
| P2 + P3 抽取 | gpt-4o-mini（每条消息并行） | ~$0.0001-0.0003 |
| P5 月度 | gpt-4o（每月一次） | ~$0.005 |

预估：每日活跃用户 ~$0.01-0.04（gpt-4o-mini 比 Haiku 还便宜）。

成本兜底策略：
- `OPENAI_MODEL_MAIN` 可降级为 `gpt-4o-mini`（牺牲共情质量换价格）
- `LLM_RATE_LIMIT_PER_MIN` 卡死每分钟主力模型调用数（默认 10）
- 失败重试只 1 次，不指数退避烧钱

## 8. 安全策略

| 风险 | 应对 |
|------|------|
| **API Key 泄露** | `OPENAI_API_KEY` 仅放 `.env.local`，永不前端使用；`.gitignore` 强制忽略 |
| **CORS 攻击** | API Route 仅接受同源请求 |
| **LLM 注入攻击** | system prompt 与 user message 严格分离，禁止用户消息覆盖 system |
| **本地数据丢失** | 设置页提供"导出 JSON"，用户可手动备份 |
| **OpenAI 兼容代理风险** | 若用第三方代理 `OPENAI_BASE_URL`，建议确认对方是否记录请求；自用项目低风险 |
| **依赖漏洞** | 定期 `npm audit`；锁定 major 版本 |

## 9. 部署架构

```
开发：localhost:3000
  │
  │ git push
  ▼
GitHub 仓库（私有 repo）
  │
  │ Vercel 自动构建
  ▼
Vercel Edge Network
  │
  ├── 静态资源（public/） → 全球 CDN
  ├── API Route → Vercel Functions（Edge Runtime）
  └── SSR 页面 → Edge SSR
  │
  ▼

```

- **Vercel 项目**：1 个（Hobby Plan 免费够用）
- **环境变量**：在 Vercel Dashboard 配置 `OPENAI_API_KEY`（必填）+ `OPENAI_MODEL_MAIN` / `OPENAI_MODEL_FAST` / `OPENAI_BASE_URL`（可选）
- **域名**：先用 `qichi.vercel.app`，后续可绑定自定义域名

## 13. 风险登记

| 风险 | 严重度 | 应对 |
|------|--------|------|
| LLM "AI 味" 严重 | 高 | Prompt few-shot 反复打磨 + 真实数据验证 |
| IndexedDB 跨浏览器兼容性 | 中 | Dexie 内部处理；Safari 私密模式会限制，提示用户 |
| 用户清缓存丢数据 | 中 | 设置页明显位置放"导出 JSON"按钮 |
| Vercel 免费版函数超时 | 低 | API Route 设置 maxDuration 30s，gpt-4o 调用一般 < 5s |
| OpenAI API 不稳定 | 低 | 已实现降级（P1 失败提示重试，P2/P3 失败默默跳过） |
| GPT 生成中文偶尔串英文 | 低 | system prompt 强约束"中文回复"；few-shot 全中文示例 |
| **免费代理 SDK timeout 不生效** | 中 | 已用 `AbortController` 强制 30s（ADR-010） |
| **chatanywhere 免费层对长 prompt 503** | 中 | 引入 `LLM_DISABLE_FEWSHOT` 环境变量可关掉 few-shot；推荐换付费 key |
| **JSON mode 在某些代理 / 旧模型不可用** | 低 | gpt-3.5-turbo 不支持，建议用 gpt-4o-mini 跑 P2/P3 |
| **JSON 导出文件大小** | 低 | 4 张表全 dump，半年数据约 200KB-1MB；浏览器原生下载即可 |

## 14. 决策记录（ADR）

| ID | 决策 | 理由 |
|----|------|------|
| ADR-001 | 砍掉每日情绪卡片 | 与"暂时停靠"气质冲突，弹窗有"打卡感" |
| ADR-002 | 砍掉宠物喂食/抚摸 | 顶部 fixed 宠物形象无交互空间 |
| ADR-003 | 名字固定（栖栖/迟迟） | 减少取名屏，2 步进核心 |
| ADR-004 | 不引入 Lottie | 静态图 + Framer Motion 足够，降低制作成本 |
| ADR-005 | OPPO Sans 单字体族 + Light/Regular/Medium 三档 | 圆润现代，杜绝楷书/宋体 |
| ADR-006 | 视觉资产命名英文化 | 代码内引用更友好 |
| ADR-007 | LLM 走 OpenAI 格式（gpt-4o + gpt-4o-mini） | 生态成熟、JSON mode 稳定、`OPENAI_BASE_URL` 可切代理 |
| ADR-008 | 删除复盘**级联**删除同 messageId 情绪，但隐藏**不级联** | 隐藏 = "我不想看了"，情绪还真实；删除 = "这段没发生过"，曲线对应点也消失 |
| ADR-009 | 月度总结**缓存 localStorage**，不加 summaries 表 | 避开 IndexedDB 版本迁移；月内首次访问生成、之后秒开 |
| ADR-010 | OpenAI SDK 超时不可靠，用 `AbortController` 强制 30s | chatanywhere 等免费代理在 SDK 配置的 timeout 下不生效，会等十分钟 |
| ADR-011 | 聊天 / 设置 / 欢迎用整页背景图替代 SVG 装饰 | 单图水彩比 SVG 散点更自然；通过 `next/image` 自动 WebP 压到 ~300KB |
| ADR-012 | 装饰分 3 层（BgImage / DecorBackground 动画 / Particles） | 背景静态，动画 SVG 只在小本本+曲线，粒子全局；分层后每页性能可控 |
| ADR-013 | 视口锁死 `html/body { height: 100dvh; overflow: hidden }` | 否则内容多时 TabBar 被推下屏，移动端切 Tab 体验差 |
| ADR-014 | 气泡用渐变 + backdrop-blur 不用纯色 | 整页背景图加上后，纯色气泡显呆；渐变 + 微 blur 像浮在空气中 |
